# Batch 2026-10 (issues published 2026-10-14 to 2026-10-22)

Times are UTC+8.

## 1. LiteLLM 1.107.0 supply-chain poisoning (highest priority)
Only `litellm==1.107.0` is affected: PyPI 10/21 19:39–21:23, Docker Hub 19:46–22:20, GHCR until
21:51. A poisoned environment runs malicious code every time Python starts, steals cloud, SSH,
GitHub, npm, PyPI and AI-tool credentials, and installs a backdoor.
Source: https://docs.litellm.ai/blog/security-incident-oct-21-2026

1. Do not run any Python (including pip). Check with the shell only:
   - `find / -xdev \( -name cook.pth -o -name cook.py \) -path '*site-packages*' 2>/dev/null`
   - `find / -xdev -path '*site-packages*' -name sitecustomize.py 2>/dev/null` and inspect each one
   - `ls -la /tmp/remote_code_loader.lock /tmp/.pc_once_72129118c59f5636c0bb`
   - `find / -xdev -path '*site-packages/litellm-*.dist-info/METADATA' 2>/dev/null | xargs -r grep -H '^Version:'`
   - `docker images` and `docker ps -a`: look for `berriai/litellm` and `ghcr.io/berriai/litellm`; note tags and creation times
2. If anything matches:
   - Delete `cook.pth`, `cook.py` and any suspicious `sitecustomize.py` using the shell.
   - Find the process holding `/tmp/remote_code_loader.lock` with `lsof` or `fuser` and kill it.
   - Pin litellm to 1.106.2 and rebuild the virtual environment or container.
   - Remove the affected Docker images and re-pull by pinned version or digest.
   - List every credential the device can reach (`~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.npmrc`,
     `~/.pypirc`, AI tool configs, tokens in environment variables) and have the user rotate them
     from a clean device. Do not rotate on the infected device.
3. If nothing matches, report the environments and images that were checked.

## 2. Node.js October 2026 security releases
Brotli out-of-bounds write, TLS hostname verification bypass, `dns.resolve` NUL truncation.
Fixed in 22.23.4, 24.22.1 and 26.12.1.
Source: https://nodejs.org/en/blog/vulnerability/october-2026-security-releases
- Check `node -v`, every version installed through nvm/fnm/volta, the Node bundled with
  self-hosted CI runners, and `node:*` Docker images.
- Upgrade to the fixed release of the same major version. Unsupported majors (such as 20.x) move
  to 22.23.4 or later.
- Rebuild images and services that depend on Node, then restart them (confirm first for
  production services).

## 3. curl / libcurl CVE-2026-92392
Affects 8.12 to 8.22. Fixed in 8.23.0.
- Check `curl -V` and the distribution's libcurl package version. If in range, upgrade through
  the system package manager when a fixed package exists; otherwise report it.

## 4. MCP TypeScript SDK CVE-2026-111767
Fixed in `@modelcontextprotocol/sdk` 1.32.0.
- Check projects and global installs on the device (`npm ls -g`, each project's lockfile).
  Upgrade anything below 1.32.0.

## 5. HTTP/3 QPACK amplification leading to memory exhaustion
Source: https://openwall.com/lists/oss-security/2026/10/22/1
- Check whether the device serves HTTP/3 (UDP 443 listeners, QUIC settings in nginx, Caddy or Envoy).
- Upgrade quic-go to 0.57.0 or later, quiche to 0.29.3 or later, lsquic to 4.9.0 or later.
- The `h3` crate and Bun 1.4.x have no fix yet: set `max_field_section_size` on `h3`, and do not
  expose Bun over HTTP/3.
- Unfixed as of 2026-10-20 also includes aioquic/mitmproxy (pass `--set http3=false`). Wireshark is
  fixed in 4.6.2 / 4.4.12. Not affected: Google quiche, IIS, Envoy, ngtcp2/nghttp3.
- Caddy serves HTTP/3 on UDP 443 by default for every HTTPS site. Check
  `go version -m $(command -v caddy) | grep quic-go` (needs 0.57.0 or later), or set
  `servers { protocols h1 h2 }` in the global options until it is upgraded.

## 6. Linux kernel CVE-2026-98260
Use-after-free in POSIX CPU timers on exec, exploitable by a local unprivileged user. Affects 5.7
and later.
- Check `uname -r`. Upstream fixes: 6.6.158, 6.12.112, 6.18.54, 7.2.8. There is no upstream fix
  yet for 5.10 or 6.1, and NVD lists no mitigation.
- Servers and desktops: upgrade to a distribution kernel that includes the fix, then reboot
  (confirm before rebooting).
- Vendor BSP devices: report the kernel version and its source only. Do not change the kernel or
  system settings such as user namespaces, which can break sandboxes. Mark "Needs vendor patch".

## 7. eMudhra (emSign) intermediate CA key compromise
The private keys of eight eMudhra intermediate CAs can be recovered from their certificates
(disclosed 2026-10-20), so anyone can issue a certificate for any host. The intermediates chain to
"emSign ECC Root CA - G3" and, through Sectigo cross-signs, to "AAA Certificate Services". Removing
the emSign root alone is not enough: use a runtime that blocks the intermediate keys, or a trust
store that drops both paths.
Sources: https://emudhra.we-have-a-problem.com/ ,
https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576 ,
https://github.com/golang/go/issues/82345

Fixed in:
- System ca-certificates: Ubuntu 20260816ubuntu0.22.04.1 / .24.04.1 / .26.04.1; Debian
  20250419~deb12u2, 20250419+deb13u1; Alpine 20261020-r0; Fedora 2026.2.92_v9.0.319; NSS 3.131.1
- Python: certifi 2026.10.19, pip 26.2.2, uv 0.13.4, sigstore 4.5.1, pixi 0.82.1
- Go 1.26.10 / 1.27.3 (CVE-2026-111943); Node.js 22.23.4 / 24.22.1 / 26.12.1
- Rust: rustls-webpki 0.103.16 (blocks the keys); webpki-roots / webpki-root-certs 1.0.10 (removes
  the emSign root only)
- Java 27.0.1.0.2, 25.0.5.0.2, 21.0.13.0.2, 17.0.21.0.2, 11.0.33.0.2, 8u511 (tracker). Oracle alert
  CVE-2026-91403 (JSSE, CVSS 9.1) covers the same branches but does not name eMudhra.
- Bun: no fix yet.

Check:
- From each device, with each client that matters (curl, system Python, every venv, Node, Go
  binaries, Java): `curl -sS https://dv-g3b-emudhra.we-have-a-problem.com/` and
  `https://dv-g3b-aaa-emudhra.we-have-a-problem.com/`. A certificate error is a pass.
- `python -m pip --version` and the certifi version in every venv and image; `uv --version`;
  `pixi --version`; `go version <binary>` for deployed Go binaries; `node -v`; `java -version`;
  `cargo tree -i rustls-webpki`.
- Container images built before 2026-10-20: ca-certificates version inside (`dpkg -s` / `apk info -v`).
- macOS: /usr/bin/curl, git, python3, perl, ruby and openssl read /etc/ssl/cert.pem, which still
  contains the roots.
- Android / vendor BSP: list /system/etc/security/cacerts and /apex/com.android.conscrypt/cacerts
  and look for the emSign and AAA Certificate Services certificates.

Fix:
- Upgrade to the versions above. Install pip by direct wheel URL with its sha256 (see the Python
  advisory), or run `UV_SYSTEM_CERTS=true uv self update` once the system store is fixed.
- Rebuild and redeploy every image and Go/Rust binary built before the fix. A fixed toolchain does
  not fix an old binary.
- Linux without a fixed package: distrust "emSign ECC Root CA - G3" and "Comodo AAA Services root"
  in /etc/ca-certificates.conf, then run update-ca-certificates. Test first; removing AAA can break
  legacy chains.
- macOS: apply the tracker's cert.pem filter and PIP_CERT workaround after the user confirms.
- Vendor BSP / Android: do not edit the system store. Report what it contains and mark "Needs
  vendor patch". Apps that only talk to your own servers can pin those servers' CA or key in their
  network security config.
- Anything that receives config, policy or commands over HTTPS without a signature on the payload
  can be taken over by interception (a public demo enabled adbd on a smart speaker this way).
  Confirm these payloads are signed.

## 8. nginx 1.30.6 / 1.31.7 security release (2026-10-14; out-of-band alert 2026-10-21)
Sources: https://nginx.org/en/security_advisories.html , https://nginx.org/en/CHANGES-1.30
Fixed in 1.30.6 (stable) and 1.31.7 (mainline). Vulnerable: 1.30.5 and earlier, 1.31.6 and earlier.
- CVE-2026-15176: buffer overflow when `alias` maps a URI changed by `rewrite` to a file (0.1.29
  and later).
- CVE-2026-93479: buffer overflow evaluating string expressions with variables (document root,
  request logging; http and stream). Affects 1.30.0–1.30.5 and 1.31.2–1.31.6.
- CVE-2026-95101: HTTP/3 unknown-frame data treated as request body; bypasses
  client_max_body_size or injects into proxied requests (1.25.0 and later).
- CVE-2026-97629: TLS session ticket key rotation leaves one key uninitialized; sessions can be
  forged (1.23.2 and later).
- CVE-2026-97205: use-after-free with AIO and SSI `include virtual` (0.8.11 and later).

Check:
- `nginx -v`, or `docker exec <container> nginx -v`; images by tag and digest; distribution
  package version.
- `nginx -T` for `alias` combined with `rewrite` or `$request_filename`, `aio`, `ssi on`, `map`
  with unnamed regex captures, `listen ... quic`, `ssl_session_tickets`.

Fix:
- Upgrade to 1.30.6 / 1.31.7 or later (or the distribution's patched package); pin images to the
  exact patch version or digest, re-pull and restart (confirm first for production).
- Until upgraded: avoid `alias` inside rewritten locations and `$request_filename`; disable `aio`
  or `ssi`; use named regex captures; turn off HTTP/3 (`quic`); set `ssl_session_tickets off`.

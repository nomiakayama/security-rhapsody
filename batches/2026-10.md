# Batch 2026-10 (issues published 2026-10-20 to 2026-10-22)

Times are UTC+8.

## 1. LiteLLM 1.107.0 supply-chain poisoning (highest priority)
Only `litellm==1.107.0` is affected: PyPI 10/21 19:39–21:23, Docker Hub 19:46–22:20, GHCR until
21:51. A poisoned environment runs malicious code every time Python starts, steals cloud, SSH,
GitHub, npm, PyPI and AI-tool credentials, and installs a backdoor.
Source: https://docs.litellm.ai/blog/security-incident-oct-21-2026

1. Do not run any Python (including pip). Check with the shell only:
   - `find / -xdev \( -name cook.pth -o -name cook.py \) -path '*site-packages*' 2>/dev/null`
   - `find / -xdev -path '*site-packages*' -name sitecustomize.py 2>/dev/null` and inspect each one
   - `ls -la /tmp/remote_code_loader.lock /tmp/.pc_once_72129118c59f5636c0bb`
   - `find / -xdev -path '*site-packages/litellm-*.dist-info/METADATA' 2>/dev/null | xargs -r grep -H '^Version:'`
   - `docker images` and `docker ps -a`: look for `berriai/litellm` and `ghcr.io/berriai/litellm`; note tags and creation times
2. If anything matches:
   - Delete `cook.pth`, `cook.py` and any suspicious `sitecustomize.py` using the shell.
   - Find the process holding `/tmp/remote_code_loader.lock` with `lsof` or `fuser` and kill it.
   - Pin litellm to 1.106.2 and rebuild the virtual environment or container.
   - Remove the affected Docker images and re-pull by pinned version or digest.
   - List every credential the device can reach (`~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.npmrc`,
     `~/.pypirc`, AI tool configs, tokens in environment variables) and have the user rotate them
     from a clean device. Do not rotate on the infected device.
3. If nothing matches, report the environments and images that were checked.

## 2. Node.js October 2026 security releases
Brotli out-of-bounds write, TLS hostname verification bypass, `dns.resolve` NUL truncation.
Fixed in 22.23.4, 24.22.1 and 26.12.1.
Source: https://nodejs.org/en/blog/vulnerability/october-2026-security-releases
- Check `node -v`, every version installed through nvm/fnm/volta, the Node bundled with
  self-hosted CI runners, and `node:*` Docker images.
- Upgrade to the fixed release of the same major version. Unsupported majors (such as 20.x) move
  to 22.23.4 or later.
- Rebuild images and services that depend on Node, then restart them (confirm first for
  production services).

## 3. curl / libcurl CVE-2026-92392
Affects 8.12 to 8.22. Fixed in 8.23.0.
- Check `curl -V` and the distribution's libcurl package version. If in range, upgrade through
  the system package manager when a fixed package exists; otherwise report it.

## 4. MCP TypeScript SDK CVE-2026-111767
Fixed in `@modelcontextprotocol/sdk` 1.32.0.
- Check projects and global installs on the device (`npm ls -g`, each project's lockfile).
  Upgrade anything below 1.32.0.

## 5. HTTP/3 QPACK amplification leading to memory exhaustion
Source: https://openwall.com/lists/oss-security/2026/10/22/1
- Check whether the device serves HTTP/3 (UDP 443 listeners, QUIC settings in nginx, Caddy or Envoy).
- Upgrade quic-go to 0.57.0 or later, quiche to 0.29.3 or later, lsquic to 4.9.0 or later.
- The `h3` crate and Bun 1.4.x have no fix yet: set `max_field_section_size` on `h3`, and do not
  expose Bun over HTTP/3.

## 6. Linux kernel CVE-2026-98260
Use-after-free in POSIX CPU timers on exec, exploitable by a local unprivileged user. Affects 5.7
and later.
- Check `uname -r`. Upstream fixes: 6.6.158, 6.12.112, 6.18.54, 7.2.8. There is no upstream fix
  yet for 5.10 or 6.1, and NVD lists no mitigation.
- Servers and desktops: upgrade to a distribution kernel that includes the fix, then reboot
  (confirm before rebooting).
- Vendor BSP devices: report the kernel version and its source only. Do not change the kernel or
  system settings such as user namespaces, which can break sandboxes. Mark "Needs vendor patch".

## 7. eMudhra CA private key compromise
- Check whether the system trust store, and the stores bundled with Node, Java and Python certifi,
  still trust eMudhra root certificates.
- System trust store: remove via the ca-certificates update. Upgraded Node releases already drop
  it. For other runtimes with bundled stores, report the version.
